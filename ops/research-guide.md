# 金融数学专业研究生项目调研与分享指南（含网站知识库文件规范）

> **指南版本**：v1.0（2026-10-18）  
> **适用场景**：班会逐校分享、大模型 / Agent 自动调研、单校 PDF 阅读版、后续多校知识库与 GitHub Pages 网站。  
> **核心原则**：**每所大学一份结构统一的 Markdown（`.md`）主文件**，用它派生 PDF 和网站页面；不以 PDF、Word 或 HTML 作为唯一资料源。


> **目的**：面向金融数学专业本科生，了解不同研究生项目的培养内容、录取方式、申请准备与毕业去向，为保研、考研和境外申请提供信息参考。
>
> **调研对象**：仅考虑**全日制硕士**；不纳入非全日制项目、MPhil 或以独立研究为主要培养方式的境外研究型硕士。境外项目以授课型、职业导向型硕士为主。
>
> **届别说明**：若本班为2024级四年制本科生，主要关注**2028年入学**的项目。若该届招生简章尚未公布，可参考前1—2届官方信息，但必须注明实际对应的入学年份，不能视作2028年的既定要求。

## 一、调研哪些专业

**内地院校**：不要只找名称中含“金融数学”或“统计学”的专业，还应覆盖：
- **数理与统计类**：统计学、应用统计、金融数学、金融工程及相关研究方向。
- **金融及交叉类**：金融硕士（MF）、金融学、金融科技、数量金融、风险管理、精算及其他适合数理背景学生的金融类项目。
- 同一院校的相关项目可能分属数学学院、统计学院、经济学院、金融学院、管理学院等；注意区分**学术硕士/专业硕士**和**推免/统考**招生渠道。

**香港、新加坡、美国及其他境外院校**：除统计、应用数学、金融数学、金融工程、量化金融外，还可查金融学、金融科技、商业分析（Business Analytics）、数据科学（Data Science）、运筹与分析（Operations Research/Analytics）等方向。

**特别注意**：不能仅凭 MS、MSc、MA 等学位缩写判断是否为授课型硕士；美国的 MEng、MFE、MFin、MPS 等职业型项目也值得关注。须以**项目官网对培养方式、学位要求和招生方式的说明**为准。有课程项目或毕业论文，不必然意味着它属于应排除的研究型项目。

## 二、每个项目重点查什么

### 1. 项目定位与基本信息

- 学校、院系、**项目完整名称（中英文）**、校区/城市、学位类型及全日制属性。
- 学制、入学季、主要培养方向；项目侧重**金融业务、数量建模、统计分析还是计算与编程**。
- 招生规模；内地项目尽量区分推免和统考名额。境外项目的招生人数及生源构成**仅在官方公布时填写**。

### 2. 录取途径与申请要求

- **内地保研**：本校取得推免资格的条件、目标学校的申请资格；夏令营、预推免、正式推免的报名、考核和录取安排；笔试/面试重点。
- **内地考研**：是否通过统考招生；招生专业与方向代码、初试**各科名称和代码**、指定教材或考试范围；复试形式、计分规则、是否考专业基础/英语等。
- **境外申请**：GPA、语言成绩、GRE/GMAT（必需、可选或豁免）、数学/统计/编程/金融先修课程、工作或实习经验要求；成绩单、CV、个人陈述、推荐信、面试等材料；申请轮次或滚动录取方式。

### 3. 竞争情况与申请难度

- **内地统考**：近2—3年招生计划、复试线、复试名单、拟录取人数及录取分数（以公开资料为准）；关注实际统考名额、复试差额和专业课特点。
- **内地推免**：是否接收外校推免生、公开的入营/考核条件和考核方式；不将经验帖中的“背景偏好”当作官方门槛。
- **境外申请**：区分官网的**最低资格要求**与实际竞争情况。只有官方公布时才引用录取率、录取者成绩分布等数据；个人录取案例只能作参考。
- 不要求给项目主观打分，也不要凭传闻断言“压分”“保一志愿”或“录取容易”。

### 4. 课程与培养方式

- 选出**3—5门代表性核心课程**及有特色的选修方向，说明课程是偏理论、金融应用还是编程实践。
- 关注 Python/R/C++/SQL 等技能要求、项目实践（Capstone）、实习安排、毕业论文或研究项目要求。
- 结合金融数学本科课程，指出所需的关键**先修知识**和可能存在的能力差距。

### 5. 费用与毕业去向

- **费用**：学费、学制内预计生活费用、奖学金/资助机会；境外项目以当地货币列示，并注明信息对应年份。
- **就业**：优先找**该硕士项目**的官方就业报告，关注就业行业、岗位、地域、典型雇主，以及继续读博的比例（如有）。
- 就业数据注明**毕业届别、统计口径和覆盖范围**；院系或全校报告不可当作某个项目的就业成果。薪资、就业率和国际学生就业情况仅在有可靠来源时列出。
- 如涉及赴境外就业，可补充官网明确说明的实习机会、职业服务及国际学生相关限制，但不要将获得就业机会视为保证。

### 6. 对金融数学本科生的适配性

用简短文字回答：**该项目适合什么目标的同学？** 例如量化研究/金融工程、银行证券与资产管理、风控、数据分析/商业分析、继续研究等。指出其最重要的优势和限制，并说明判断依据；避免只用学校排名下结论。

## 三、三条升学路径的总体时间线

以下按**2028年秋季前后入学**作示意；具体年份、月份和截止日均须以届时招生通知为准，部分境外项目可能存在更早的申请批次或不同入学季。

| 本科阶段 | 保研 | 考研 | 境外申请（港新美等） |
|---|---|---|---|
| **大三上：2026年秋** | 了解本校推免办法、目标项目及科研/竞赛准备 | 确定备选专业，比较考试科目与跨专业要求 | 初选专业；核对先修课、语言及GRE/GMAT要求 |
| **大三下至暑期：2027年春夏** | 准备夏令营/其他提前选拔、面试材料 | 按目标专业课和统考科目系统备考 | 准备语言考试、推荐人、CV、文书、实习/科研材料；留意提前申请 |
| **大四上：2027年秋** | 关注预推免、正式推免及录取确认 | 关注招生目录变更、网报及网上确认 | 进入不少项目的主要申请季；按各项目轮次递交材料 |
| **2027年冬—2028年春** | 已录取者关注后续要求 | 参加初试；随后关注成绩、复试和调剂 | 继续申请、面试，比较录取结果与奖学金条件 |
| **大四下：2028年春夏** | 完成毕业及入学手续 | 关注最终录取并完成毕业手续 | 确认入学、缴纳必要费用、办理签证及住宿等 |

**分享时应额外列出所调研项目的具体时间节点**：招生信息发布时间、报名/网申开放和截止日、考核/面试时间、结果公布、接受录取截止日。未发布2028年安排的，明确标注“参考2027年入学批次”，不要将上一届日期直接平移一年当作已确定日期。

## 四、去哪里找信息

**优先使用官方来源：**

- **内地**：目标学校研究生院（研究生招生网）、相关学院网站、招生专业目录、招生简章、推免/夏令营通知、复试办法、拟录取名单、培养方案、就业报告；[中国研究生招生信息网](https://yz.chsi.com.cn/)及其[推免服务系统](https://yz.chsi.com.cn/tm)。
- **港新美等**：学校和具体项目官网的 *Admissions / Entry Requirements / Application Deadlines / Curriculum / Tuition & Funding / Career Outcomes / Employment Report / FAQ* 页面及官方宣讲资料。
- **补充核对**：公开的历年录取名单、往届校友经验、知乎、一亩三分地、LinkedIn 等，可用于了解实际体验和信息线索，但必须明确其非官方性质。

**信息记录规则：**

1. 对**申请条件、考试科目、日期、费用、招生和就业数据**，记录来源链接、对应入学/毕业年份及检索日期。
2. 官方未发布的信息写“**官网未公开**”；找到旧版信息写“**参考××年**”；不同来源不一致写“**待核验**”。不得让大模型补造数字。
3. 区分**学校、学院、具体项目**三个层级的数据，以及**招生计划、实际录取、实际报到**等不同口径。
4. 若最新招生简章尚未发布，优先查找最近一届可核实文件，并提醒同学后续复查。

## 五、如何组织班级分享

围绕已经分配的院校，优先挑选与金融数学专业联系紧密、又具有不同职业方向的全日制项目。不必罗列该校所有专业；重点讲清楚**有哪些选择、培养内容有何不同、怎样申请、什么时候准备、毕业后可能去哪里**。

建议按以下顺序组织：

1. **院校与项目概览**：列出值得关注的硕士项目及所属院系，说明不同方向的区别。
2. **项目比较**：逐项目介绍申请门槛、课程、就业和费用；可用下表汇总。
3. **三条升学路径**：按照项目实际招生方式，展示推免、考研或境外申请的重要时间节点。

## 六、每所大学的统一交付规范（必读）

### 6.1 应交付哪些文件

对每所学校，采用“一校一主文件”的原则：

1. **必交：`学校ID.md`**。这是完整、可编辑、可检索的权威内容母版，包含统一元数据、项目对比表、逐项目分析、时间线和来源清单；必须作为**真实文件**提供下载，不以聊天窗口内的文字替代。
2. **阅读版：`学校ID.pdf`**。条件允许时，同次输出供学生直接阅读的 PDF；**从同一份 Markdown 生成**，不能另写一份内容不同的 PDF。PDF 应保留中文字体、可点击的来源链接、清晰表格和分页。
3. **非必交：HTML、DOCX、CSV、JSON**。不需要每校单独编写 HTML；未来的网站会统一将 Markdown 渲染为页面。跨校 CSV 项目索引可在积累多校资料后统一生成，避免每份报告重复维护同一数据。

若工具无法生成 PDF，须明确说明，但**不得用 PDF 代替 Markdown 主文件**。未经核验的信息也不得为了填满页面而编造。

### 6.2 文件名和目录

- 文件名使用**固定的英文小写 ID**，仅含 `a-z`、`0-9` 和连字符，例如 `cn-tsinghua.md`、`cn-pku.md`、`cn-ruc.md`、`hk-hku.md`、`sg-nus.md`；不要用有空格、日期、版本号的文件名。学校 ID 一经确定，不因改名或年份变化而随意更换。
- 文档正文以中文为主；项目英文正式名称应同时保留。
- 项目与院系的原始官方名称应照实记录，不自行创造缩写或翻译。
- 如果由多人维护，所有人使用同一套目录、ID 和章节结构；不要产生 `最终版2`、`最新最终版` 等并存文件。

建议仓库结构（今后上线时直接使用）：

### 6.3 Markdown 顶部的 YAML 元数据（必需）

每份 `.md` 文件**从第一行起**以 `---` 开始，包含如下字段。示例字段值仅用于说明格式；实际生成时必须替换为已确认的信息。无法确认英文校名时可填空字符串，不能臆造。

```yaml
---
title: "清华大学研究生项目调研"
description: "金融数学本科生升学项目与申请信息参考"
content_type: school_report
school_id: cn-tsinghua
school_name_zh: 清华大学
school_name_en: "Tsinghua University"
region: china-mainland
country_or_region: 中国大陆
target_intake_year: 2028
reference_intake_years: []
researched_on: "2026-10-18"
last_verified_on: "2026-10-18"
report_status: draft
language: zh-CN
---
```

**字段与填写规则：**

| 字段 | 规则 |
|---|---|
| `title`, `description` | 网页标题与简要描述，均为字符串。 |
| `content_type` | 固定为 `school_report`。 |
| `school_id` | 跨版本不变的学校唯一 ID，与文件名一致（不含 `.md`）。 |
| `school_name_zh`, `school_name_en` | 学校官方中英文名称；无可核实英文名写 `""`。 |
| `region` | 固定选用 `china-mainland`、`hong-kong`、`singapore`、`united-states`、`other` 之一，便于网站分类。 |
| `country_or_region` | 面向学生显示的国家/地区名称。 |
| `target_intake_year` | 本班统一设为 `2028`，表示**关注目标**，不代表 2028 招生信息已经发布。 |
| `reference_intake_years` | **实际核实并引用过**的历史入学年份，如 `[2027, 2026]`；若尚未找到可核实资料，填 `[]`。 |
| `researched_on` | 实际开展调研的日期（`YYYY-MM-DD`）。 |
| `last_verified_on` | 最近一次逐项核验来源的日期；未复核不得擅自刷新此日期。 |
| `report_status` | `draft`（草稿）、`reviewed`（已人工复核）或 `needs_update`（需更新）；不得把自动生成当作人工复核。 |
| `language` | 固定为 `zh-CN`。 |

**注意**：元数据里的 `last_verified_on` 只代表这份报告最后核验时间，**不能替代各关键事实旁的适用年份和来源记录**。

### 6.4 项目唯一 ID 与统一字段

- 每个正式纳入的硕士项目都设置一个稳定的 `program_id`，例如 `cn-tsinghua-p001`、`cn-tsinghua-p002`。对应同一个项目的推免、统考和其他招生渠道，原则上保留同一项目 ID，再在其内部区分渠道；如果招生单位、学位名称或培养方案确实不同，则另设项目 ID。
- 项目更名但本质延续时，保留原 ID，并注明曾用名；两个独立项目不能共用一个 ID。ID 仅用于管理，**不代表项目质量、名次或申请难度**。
- 所有项目采用相同的核心字段：`项目ID`、`院系`、`中英文项目名`、`学位与全日制属性`、`学制与入学季`、`培养方向`、`招生途径`、`申请/考试要求`、`关键日期`、`竞争信息`、`代表课程与先修知识`、`费用与资助`、`项目级就业信息`、`金融数学适配性`、`官方来源`。
- 只有**确认符合“全日制、非 MPhil、境外非独立研究型硕士”**范围的项目才进入正式的项目列表；范围不清楚的项目可记录在“待核验”中，不能直接计入。
- 对于不适用的字段写“**不适用**”；不存在可公开核实数据写“**官网未公开**”；已发现矛盾或尚未确认写“**待核验**”；只有历史资料时写“**参考 2027 年入学批次**”等明确文字。**不要把空白、零、未知和不适用混为一谈。**

### 6.5 链接与事实引用标准

1. **关键事实须就近附直接、可点击的 Markdown 原始来源链接**，包含适用招生/毕业年份与检索日期。关键事实包括但不限于考试科目和代码、录取资格、录取名额、历年分数、费用、奖学金、申请截止日期、就业率及薪资。
2. 推荐正文写法：`学费：……（[S03：项目收费说明](真实官方URL)，适用 2027 年入学，检索 2026-10-18）`。此处 `真实官方URL` 只是**格式示例**，正式文件必须替换为真正可访问的链接。
3. 所有来源统一编号 `S01`、`S02`……，在报告末尾登记；相同来源可重复引用，不必反复产生编号。**正文紧贴数据的链接和末尾来源表都要保留**，便于网页阅读及后续追溯。
4. 优先项目官网、学院通知、研究生院或招生网、官方就业报告。非官方资料必须标明为“补充线索/非官方”，不得充当入学门槛或就业数据的唯一依据。
5. 对同一事实出现的新旧或相互冲突的官方文件，分别保留链接、发布日期及适用年度，并标为“待核验”，避免无依据地择一。
6. 链接尽量指向具体招生公告、培养方案、费用或就业报告页面，而不是只有学校主页。官网链接失效时，标注原始链接和失效/待复查状态，不以记忆补足事实。
7. **2028 年信息尚未发布**时，明确使用哪一届资料；绝不能把 2027 年截止日期机械加一年作为已公布的 2028 年日期。

## 八、为后续合并手册和 GitHub 网站预留的规则

1. **一校一页、可独立阅读**：每篇报告有完整学校标题、项目简介、官方来源和核验日期，不依赖其他大学文件才能理解。
2. **统一结构和字段**：章节固定为上述 1—8；项目采用稳定 ID、统一的字段名称；同名招生路径不能在不同学校中使用含义不同的字段。
3. **Markdown 原生语法优先**：使用 `#` 标题、Markdown 表格、列表、普通超链接。避免图片式表格、整页截图、复杂 HTML/CSS、人工分页和仅在 Word/PDF 中可见的信息；这样可以被 VitePress 等静态网站生成器直接渲染。
4. **链接与附件可移植**：外部官方材料使用绝对 `https://` 链接；仓库内的图片、附件使用相对路径。不得把本地 `/mnt/data/` 路径写入正式正文。
5. **PDF 不承担数据维护职能**：内容修订先修改 `.md`，再重新导出 PDF；不要单独编辑 PDF 导致两种版本不一致。
6. **项目索引将来统一生成**：各校对比表字段一致后，可形成“一项目一行”的 `programs.csv`，包含 `school_id`、`program_id`、地区、项目中英文名、院系、学位、全日制、学制、招生途径、数据年度、最近核验日期、来源链接、Markdown 文件路径等字段。没有可靠值时使用统一状态标记，不填虚构数字。
7. **跨校比较不得混淆数据口径**：例如不同币种学费、年份不一的申请轮次、全校和项目层面的就业率均应原样标注，未经必要调整不可直接比较。
8. **版本更新**：更新招生信息时修改原学校文件并添加“更新记录”；保留历史适用年份与变更说明，不将旧数据无声覆盖为“最新”。
9. **发布前核验**：检查 Markdown 能正常渲染、表格列数一致、内部路径正确、官方链接可访问、无占位符、无未注明届别的截止日期，并核对 PDF 与 MD 内容一致。
